## تحديث تثبيت قائم

أوقف **مشرف التشغيل** بـCtrl+C في جلسته وانتظر انتهاء البوت، ثم من مجلد Khaled نفسه:

```bash
git pull --ff-only
source .venv/bin/activate
python -m pip install -r requirements.txt
```

احتفظ بمجلد `runtime` وملف `.env` كما هما. حالة4.0.x و4.1.0 لا تحتاج تصفيرًا أو ترقية سياسة عند هذا التحديث. لا تشغّل تثبيتين على حساب Demo نفسه؛ قفل الحساب محلي داخل مجلد الحالة.

حمّل إعدادات الاتصال المحلية ثم افحص وشغّل كما في الخطوات التالية. إذا رفض Git التحديث بسبب تعديلات محلية، راجعها قبل استبدال أي ملف.

## تثبيت جديد داخل Ubuntu على Termux

هذه الأوامر تخص بيئة Ubuntu داخل Termux، مع Python3.11 أو أحدث:


إذا كان للحساب تثبيت قائم، استخدم أحدث حالته بدل بدء دفتر فارغ. لا يغيّر أي أمر تثبيت مستودع Final.

## بيانات الاتصال المحلية

للتثبيت الجديد فقط:

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

املأ `BINANCE_API_KEY` و`TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`. للمصادقة اختر طريقة واحدة: `BINANCE_API_SECRET` لـHMAC، أو`BINANCE_RSA_PRIVATE_KEY_PATH` لملف RSA محلي بصلاحية0600 مع ترك HMAC فارغًا. لا ترفع القيم إلى Git أو المحادثة.

في **كل جلسة تشغيل جديدة** فعّل البيئة وحمّل الملف:

```bash
source .venv/bin/activate
set -a
. ./.env
set +a
```

الملف `.env` لا يُقرأ تلقائيًا عند تشغيل Python مباشرة؛ systemd يقرأه من `EnvironmentFile`. Telegram مطلوب في Demo، ويُختبر تسليم رسالة البدء قبل السماح بالدخول.

## الفحص والتشغيل

استخدم حساب Demo مخصصًا بوضع one-way وsingle-asset USDT. المصالحة تشمل الحساب كله وقد تعالج المراكز والأوامر غير المعروفة؛ لا تخلط البوت مع تداول يدوي أو بوت آخر على الحساب.

مرة واحدة للتثبيت الجديد بعد مراجعة إعدادات الحساب والمفتاح:

```bash
python tools/demo_setup.py
```

فحص للقراءة فقط، دون إرسال أوامر أو تغيير الرافعة:

```bash
python tools/demo_preflight.py
```

يتحقق من التوقيع والحساب وWebSocket والسياسة المحلية والنيات والمحاسبة والأوامر. رمز الخروج0 يعني نجاح القراءات،2 يعني وجود حالة تحتاج مراجعة،1 يعني فشل الفحص. نجاح القراءة لا يثبت قبول أوامر التداول أو الحماية.

**الأمر التالي يبدأ التداول التجريبي عند تنفيذه:**

```bash
python -u tools/supervise_demo.py
```

المشرف يعيد تشغيل البوت بعد خروجه، مع انتظار5ثوانٍ. لإيقافه استخدم Ctrl+C في **جلسة المشرف**؛ إيقاف الابن وحده يؤدي إلى إعادة تشغيله. يمكن التشغيل المباشر دون مشرف بـ`python -u run_demo.py`.

في جلسة مستقلة، حمّل `.env` ثم شغّل مراقب الصحة:

```bash
python -u tools/watch_health.py
```

يفحص المراقب كل10ثوانٍ وينبه على Telegram عند تغير healthy/degraded/offline. وصول التنبيه يعتمد على عمل المراقب والاتصال وTelegram. داخل Termux أزل قيود البطارية محليًا واستخدم wake lock حيث يتوفر؛ لا يوجد ضمان استقرار أسبوعين قبل الاختبار الفعلي.

## Kill Switch والاستعادة

| البيئة | الوضع | مهلة WS / أخطاء API بالدقيقة / السبريد / DD / الخسائر |
|---|---|---|
| Paper وBinance Demo |`observe`: تسجيل وتنبيه فقط |300ث /30 /15× /15% /10 |
| testnet المستقل في طبقة السياسة |`soft`: منع دخول600ث ثم تعافٍ بعد زوال السبب ومصالحة ناجحة |120ث /15 /10× /10% /6 |
| Mainnet في طبقة الحماية |`hard` مفروض ويغلق عند التفعيل |60ث /10 /8× /5% /4 |

اسم اتصال Demo ومجلد حالته في الكود هو`testnet`؛ عنوان Binance Demo يصنفه فعليًا`demo` ويلزمه observe. وجود سياسة hard لا يفتح Mainnet في المشغل المعتمد.

observe لا يوقف الدخول بسبب عتبات Kill Switch، لكن شروط سلامة التنفيذ باقية: لا أمر مالي دون WAL ناجح، ولا دخول قبل المصالحة، ولا إعادة إرسال POST غامض، ولا دخول رمز بإدارة حماية معلقة. تبقى معالجة فشل حماية الرمز قائمة كما كانت.

- WebSocket يعاود الاتصال مع backoff وعشوائية حتى60ثانية، مع الإبقاء على فحص حداثة بيانات الإشارة.
- API Circuit Breaker يوقف GET مؤقتًا بعد30فشلًا، ويختبر محاولة واحدة بعد30ثانية. ميزانية طلب GET الكامل30ثانية؛ لا يعيد POST ماليًا بشكل أعمى.
- WAL يسجل ويفرض fsync قبل حفظ الحالة والإجراءات المالية. الاستعادة تحمل آخر الحقائق ثم تصالح Binance بنفس معرّفات الأوامر؛ لا تعيد تنفيذ الأوامر من السجل.
- يُتجاهل آخر سطر WAL ممزق فقط؛ التلف الداخلي يمنع بدء التداول. امتلاء القرص يمنع الأوامر غير المسجلة، وتلزم كتابة متينة ومصالحة قبل استئناف الدخول.
- Watchdog يطلب إعادة تشغيل العملية عند تعليق المكونات أو تجاوز1.5GB أو10000ملف مفتوح. انقطاع السوق مختلف عن تعليق العملية.

SIGINT/SIGTERM يمنع الدخول، ويمهل الإجراء الجاري حتى ثانيتين، ثم يحفظ ويغلق الاتصالات. **لا يغلق المراكز ولا يلغي أوامر الحماية**. تبقى آخر حماية مؤكدة على Binance؛ متابعة التريل برمجيًا تحتاج البوت يعمل. أي أمر جارٍ لم يُحسم يحتاج الاستعادة والمصالحة عند البدء.


هذا مسار Paper مفروض ببيانات السوق العامة، مستقل عن حساب Demo ومفاتيحه وحالته، ولا يرسل Telegram. يعرض السياسة الحالية وحالة الملاحقة وأسباب الإغلاق والرسوم، مع تصدير CSV وJSON. [التعليمات الكاملة](paper_dashboard/README-AR.md).

## Linux مع systemd

على خادم Linux مع systemd، ضع النسخة في`/home/khaled/Khaled` وجهّز `.venv` و`.env` ثم:

```bash
sudo bash deploy/install.sh
sudo systemctl start khaled-health khaled-bot
journalctl -u khaled-bot -f
```

التثبيت يفعل الخدمات للإقلاع التالي ولا يبدأ التداول فورًا. الخدمة تستخدم `Restart=always` دون حد يعطل التعافي بعد تكرار الانقطاع. stdout/stderr إلى journald؛ ملف logrotate مستقل للأحداث. لا تشغّل مشرف Termux وsystemd معًا على الحساب نفسه؛ systemd ليس جزءًا من Termux المعتاد.
