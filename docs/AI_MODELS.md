# نماذج Meta-Decision

النموذج الأولي Multinomial Logistic Regression بإعدادات بسيطة واستدلال Python. اخترناه لسهولة تدقيق المعاملات ولتقليل تبعيات Termux. المخرجات احتمالات الهدف والوقف وانتهاء المهلة. تعبر مؤشرات missing عن غياب التمويل أو open interest أو سياق BTC. فشل الاستدلال يرفض الإشارة. تحقق المحفظة والحجم مستقل عن النموذج.

`models.labels.label` يصنّف أول حاجز قابل للتنفيذ بعد القرار، ويستبعد المسارات ذات الفجوات. يتطلب CLI عينات JSONL تحتوي `decision_ms` و`features_ms` و`label_end_ms` و`row` و`label`. إنتاج سجل عينات سوق موسوم بالكامل يتطلب أحداثًا فعلية وخصائص لحظة القرار.

```bash
python -m models.train samples.jsonl model.json --version candidate-1 \
  --calibration-ms CALIBRATION_START --test-ms TEST_START --embargo-ms EMBARGO
```

يقصّ split التداخل بين نهاية نتيجة التدريب وبداية calibration/test، ويخرج Brier وreliability bins من البيانات المحجوزة. `walk_forward` يكرر تقسيمًا أماميًا على حدود يحددها الباحث. التدريب لا يكتب موافقة. يتطلب تحميل النموذج في Replay ملف موافقة مع `artifact_sha256` و`config_sha256` و`approved_by` و`scope: shadow`. الرجوع يكون باختيار الملف والموافقة السابقين. تدريب LightGBM/CatBoost ومقارنتهما والنموذج المعتمد معلقة على بيانات كافية.

لبناء عينات Meta-label من ملف سوق قابل لإعادة التشغيل:

```bash
python -m models.build_samples runtime/research/events.jsonl runtime/research/filters.json \
  runtime/research/samples.jsonl --horizon-ms 60000
```

تُجمّد الميزات عند القرار وتُقبل عينة فقط بعد تعبئة افتراضية في Replay. يبدأ مسار تسمية الهدف والوقف الثابتين بعد التعبئة، ويستخدم أسعارًا قابلة للتنفيذ على كمية الصفقة. تُستبعد المسارات التي لم تكتمل بسبب فجوة أو إعادة بناء للدفتر أو نهاية التسجيل. يجب أن تبقى العينة الموسومة وتسلسل الأسعار ومخرجات النموذج في بيئة البحث حتى اجتياز المقارنة ومراجعة الترقية.

يدعم `evaluation.costed` مرشحًا ثالثًا اختياريًا عبر `--model` و`--approval` المرتبطين ببصمة الإعدادات. يظل هذا المرشح في Replay. يعمل Apex Paper وقناة Demo التشغيلية بقواعد فقط. يبقى اعتماد نموذج سوق فعلي ومراقبة انجرافه على بيانات جديدة `PENDING`.

## بيانات التدريب في إصدار التأهيل

تتضمن العينات الجديدة وقت الحدث المرجعي ووقت وصول الدفتر ووقت إتاحة الميزات وأعلام نقص التمويل وOI وسياق BTC. يحتفظ `models.train` ببصمة Dataset ونوافذ التدريب والمعايرة والاختبار. يدعم `--walk-boundaries` لطيات تطوير منفصلة عن الاختبار النهائي، ويوازن الفئات في التدريب ويعرض المعايرة وتحول متوسط الميزات ومعاملات النموذج الخطي.

القرار التشغيلي Rules-Only. `HEURISTIC_SCORE` درجة قواعد، و`CALIBRATED_MODEL_SCORE` درجة نموذج خضع للمعايرة ضمن تجربة البحث. لا توجد درجة `VALIDATED_EXPECTED_NET_EDGE` معتمدة. اختبار المنظومة استعمل عينات مصطنعة، وعدد عينات السوق الجديدة المؤهلة للاعتماد صفر. لم تُدرَّب LightGBM أو CatBoost في غياب بيانات مناسبة. الرجوع البحثي يتم باختيار الأثر والموافقة المطابقين. لا يُدرَّب النموذج من مسار التشغيل.
