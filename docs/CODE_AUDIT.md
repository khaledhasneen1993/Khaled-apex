# تدقيق Champion Baseline

هذا التدقيق يخص Commit المصدر المثبت في [الترحيل](MIGRATION.md).

| المجال | السلوك عند المصدر | نتيجة الترحيل |
| --- | --- | --- |
| توليد الإشارة | يختار `ContinuousScanner` عقود USDT الدائمة، يسخّن شموع 1m، يستقبل kline، ويحسب حركة مقابل إغلاق قبل شمعتين وحجمًا جزئيًا مقابل متوسط 12 شمعة مكتملة | بقي المرجع كما هو. Shadow يطلب نافذة تداول مرصودة ويطبع الحجم بطول الفترة |
| ترتيب الفرص | 8 عمّال، طلبات دفتر محدودة، أول إشارة تكمل فحص imbalance وتملك القفل تحصل على الخانة | بقي في مسار Cascade التشغيلي. Apex Shadow يرتب المرشحين في نوافذ زمنية |
| تحقق السعر والتنفيذ | بعد التصفية يعيد `enter` تقدير الانزلاق من مستويات العمق؛ Demo يعيد استخدام `LiveExchange` وسجل intents | احتُفظ بطبقة Binance وواجهاتها. Shadow يستخدم كلفة عمق منفصلة |
| تحجيم Paper | `size_position` و`PaperExchange.create_order` يثبتان القيمة الاسمية 100، ويصل `make_position` إلى `enforce_equity_risk=False` | أزيل التجاوز. السقف هو الأصغر بين الخسارة المسموحة والحجم الاسمي والهامش المستهدف. يُراجع عند سعر التعبئة الافتراضي |
| تحجيم Demo | حقوق الحساب الحالية، رافعة ثابتة في baseline، ميزانية وقف ورسوم، bracket وprecision وliquidation | بقيت إعدادات الحجم والرافعة الموروثة، ولم تُرفع الرافعة |
| الوقف | 8% من التعبئة، تفعيل الملاحقة عند 1.5%، مسافة 0.6%، دون TP ثابت | بقي في التشغيل. جُرّبت المسافات في دراسة OHLCV محدودة؛ ATR والبنية والتعادل الصافي في Shadow |
| حساب وإغلاق | Paper يسجل افتراضيًا رسوم الدخول والخروج؛ Demo يحصّل معلومات التعبئة والمراكز والحماية عبر Binance | أضيفت حماية من تكرار دخول Paper متزامن؛ طبقة Demo تستعمل مسارها الأصلي |
| استعادة تنفيذ | `journal/wal.py` و`DurableExecution` يحفظان intent وclient ID ويصالحان الأمر. `ProtectionRecovery` يراجع الوقف وحماية الرمز. `SafetySupervisor` يستعيد الجلسة ويحمي الكتابة | بقيت الطبقة في مسار Demo؛ اختبارات الأعطال تعمل مع HTTP محاكى |
| اختلاف البيئات | Paper يملأ عند ticker افتراضي؛ Demo يتعامل مع التعبئة الجزئية والرسوم الفعلية وnative stop. لا تطابق في نمذجة التنفيذ | فصل الحالات وإبقاء الفروق صريحة |
| Kill Switch | عنوان Demo يجبر وضع observe حتى عندما توجد سياسة soft؛ توجد حواجز تنفيذ وتخزين مستقلة | Demo يستخدم soft لحجب الدخول عند تجاوز العتبات؛ أخطاء WS وAPI لا تستدعي إغلاقًا جماعيًا |
| التوثيق | README القديم يصف التحجيم من حقوق الحساب بينما أحدث تعديل Paper كان يتخطى ذلك؛ صفحة اللوحة وصفت الحجم الثابت | التوثيق والواجهة يعرضان سقف القيمة الاسمية وميزانية الخسارة |
| الاختبارات | 337 اختبارًا و9 اختبارات فرعية نجحت من المصدر، مع mock transport واختبارات استعادة وفشل حماية | حافظت Apex على المجموعة وأضيفت اختبارات بيانات وإشارات ومخاطر وبحث |
| CI | لا توجد GitHub Actions في شجرة المصدر | التحقق المذكور في تقرير الإصدار محلي |

من ميزات الاستعادة الموروثة التي بقيت موجودة WAL، وتأكيد حالة أوامر Reduce-only، والتحقق من التصفية، واستخدام Client Order IDs، واسترجاع سعر التنفيذ عند غيابه، ومصالحة التعبئات مع دفتر التنفيذ. ملفات `exchange/execution.py` و`exchange/management.py` و`exchange/reconciler.py` و`journal/wal.py` بقيت مرجعًا لهذه الضمانات.
