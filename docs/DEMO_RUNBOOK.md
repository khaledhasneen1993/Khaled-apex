# Binance USDⓈ-M Futures Demo

## التجهيز والفحص للقراءة فقط

خصص حساب Demo ومفتاحًا له وحده. اضبط One-way وSingle-Asset وIsolated للرموز المختارة من واجهة الحساب. جهّز سياسة المشغّل من `docs/operator_policy.example.json` في `runtime/testnet/operator_policy.json` بعد التحقق من حقولها. حمّل متغيرات `.env` محليًا من ملف صلاحياته 600. يتطلب تشغيل Demo الموروث تنبيهات Telegram وفق سياسة التشغيل. أبقِ Baseline على Paper عند التثبيت.

```bash
python -m tools.demo_preflight --strategy apex --instruments runtime/apex-paper/filters.json
```

يعرض الفحص `account_alias` من Binance Demo، ويتحقق من الحساب والرموز والهامش ودفتر التنفيذ. يستخدم GET فقط. لا يثبت صلاحية إرسال الأوامر أو قبول الوقف. أوقف Legacy وأي عميل آخر على الحساب قبل التأهيل. حالة Legacy القديمة قد تمنع Apex من الاستعادة حتى تُراجع. احتفظ بالدفاتر وWAL.

## موافقة التأهيل المحدود

اضبط `APEX_FENCE_URL` إلى قاعدة Upstash Redis مخصصة مشتركة بين كل الأجهزة التي قد تشغل هذا الحساب، واضبط `APEX_FENCE_TOKEN` محليًا. استخدم قاعدة دون إخلاء تلقائي للمفاتيح، وحافظ على وصولها حصريًا للمشغلين الموثوقين.

```bash
python run_demo.py --strategy apex --describe-qualification --instruments runtime/apex-paper/filters.json
```

يعرض الأمر البصمة محليًا. بعد مراجعة الكود والفحص، أنشئ `runtime/testnet/apex-approval.json` بالصلاحية 600، واملأ الحقول من القيم الفعلية:

```json
{
  "scope": "binance-demo-qualification",
  "fingerprint": "DIGEST_FROM_DESCRIBE",
  "account_alias": "ALIAS_FROM_PREFLIGHT",
  "approved_by": "OPERATOR",
  "expires_at": "ISO-8601-UTC-EXPIRATION"
}
```

المهلة بحد أقصى 96 ساعة. تغيّر الإصدار أو السياسات أو أدوات الرموز أو عنوان القفل يغيّر البصمة. انتهاء الموافقة يحجب الدخول، مع إبقاء إدارة مراكز الجلسة وحمايتها ما دام القفل متاحًا.

## بدء التأهيل بتفويض مستقل من المشغّل

```bash
python run_demo.py --strategy apex --qualification --enable-demo \
  --instruments runtime/apex-paper/filters.json --approval runtime/testnet/apex-approval.json
```

هذا الأمر قد يرسل أوامر **Demo** بعد فحوص القراءة وقفل الحساب. حد التأهيل مركز واحد، رافعة ثابتة لا تتجاوز 10×، ومخاطرة دخول مقدّرة 0.25% وحد خسارة يومي 0.5% لحجب الدخول. فجوات السوق والانزلاق قد تزيد الخسارة الفعلية. لا تتشارك Legacy الحساب. القفل ينظم عمليات Apex الملتزمة بالقاعدة المشتركة، ولا يستطيع منع عميل خارجي من التداول أو منع مسؤول القاعدة من حذف المفتاح.

عند Ctrl+C احفظ السجل وتحقق من Binance. يتحرر القفل عند إثبات خلو الحساب وحسم النوايا. عند انقطاع حاد أو وجود مركز أو نية غير محسومة يبقى القفل لحماية الحساب من الاستحواذ التلقائي. راجع المنصة وسجل التنفيذ وأوقف الكاتب الأول يقينًا قبل إزالة قفل عالق يدويًا. لا تزيل القفل اعتمادًا على انقطاع الشبكة وحده. الحماية الأصلية المؤكدة مستقلة عن لوحة التحكم.

## اختبار 72 ساعة

في جلسة طرفية مستقلة بعد بدء التأهيل بإذن المشغّل:

```bash
python -m tools.soak_demo --qualification --hours 72
python -m tools.status --mode testnet
```

المراقب محلي ولا يبدأ التداول. يتطلب الملف جلسة Apex واحدة، وعينة إغلاق فعلية، وتغطية وحماية دون ثغرات مرصودة. راجع أيضًا سجل Binance الفعلي والتعبئات والمصالحة واستعادة الاتصال. التقرير لا يفتح تشغيل Apex المستمر تلقائيًا. يلزم إصدار اعتماد مستقل بعد المراجعة. بقي هذا الاختبار معلقًا في تسليم التطوير.
