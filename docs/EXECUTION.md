# التنفيذ والاستعادة

يستمر Demo على `LiveExchange` و`DurableExecution`. يُحفظ intent ومعرّف الأمر قبل إرسال POST، ويجري الاستعلام والمصالحة عند فقدان الرد. يغطي المحاكي المراكز الفعلية والملء الجزئي وأخطاء المعدل والحماية. لا يوجد افتراض exactly-once على الشبكة. تبقى إدارة الوقف الأصلي ومصالحة أوامر الحماية ومعالجة إخفاق رمز بمفرده في طبقة Binance.

قبل دخول Cascade، يجري فحص دفاتر الأسعار وتقدير السعر القابل للتعبئة والقيود والرصيد والكمية. عند فشل التحقق تتوقف محاولة الدخول. حماية Demo التشغيلية `soft`، وحجب الدخول منفصل عن إدارة المراكز. تعطل تغذية الأسعار أو وصول تنبيه لا يطلق إغلاقًا جماعيًا.

`apex/safety.py` يصف Ready وWarning وDegraded وProtective وEmergency كسياسة للبحث. الربط الكامل بهذه الحالات في Demo وقياس التنفيذ على Binance عبر soak معلقان. Shadow ينتظر وصول عمق جديد بعد التأخير المحدد. يحاكي Replay التعبئة الكاملة افتراضيًا، ويدعم تعبئات IOC جزئية اختيارية من العمق الظاهر. يبقى وقف السوق المحاكى معلقًا حتى تُغلق الكمية كاملة.

يحوّل محول Apex Demo دخول المحاكاة المحلية إلى عقد `LIMIT/IOC` محدود السعر عبر نفس Write-Ahead Log وClient Order ID. يسوي الرد المفقود بالاستعلام عن المعرّف قبل أي قرار تالٍ، ويستخدم الكمية المنفذة في الحماية الأصلية. يرفض الإصدار التشغيلي أي محاولة Apex Demo قبل الاتصال بسبب شروط الاعتماد المعلّقة.
