# لوحة Paper المحلية — Final وKhaled

نفس شكل لوحة المتابعة المحلية السابقة، مكيّف مع Khaled الحالي. يعمل البوتان داخل عمليتين منفصلتين، بمصدر Final الأصلي من مستودعه ومصدر Khaled من هذا التثبيت. حساب جديد لكل بوت يبدأ بـ100 USDT افتراضية، بأسعار Binance USDT-M العامة الحية.

## أول تشغيل من Ubuntu داخل Termux

أوقف اللوحة أو محاكاة Paper القديمة بـCtrl+C وانتظر رجوع المؤشر. داخل مجلد Khaled الحالي:

```bash
git pull --ff-only
bash run_paper_dashboard.sh --fresh
```

للتثبيت المنفصل إن لم يوجد مجلد Khaled:

```bash
cd /root
git clone --branch main --single-branch https://github.com/khaledhasneen1993/Khaled.git Khaled-paper
cd Khaled-paper
bash run_paper_dashboard.sh --fresh
```

تحتاج Python3.11+ وgit وpython3-venv. عند الحاجة: `apt install -y git python3 python3-venv`. أول تشغيل يجلب Final ويثبت المكتبات داخل `.venv-paper-dashboard`؛ لا يحتاج ZIP أو مفاتيح أو Telegram.

افتح `http://127.0.0.1:8787` بمتصفح الهاتف. تبدأ عمليات Paper تلقائيًا، ويمكن اختيار Final أو Khaled أو الاثنين. توجد أرصدة وحقوق وهوامش ومراكز ووقف وملاحقة، سجل صفقات بصافي الرسوم، تفاصيل التنفيذ والإشارة وأسباب الخروج، حالة بيانات كل عملة، تشغيل وإيقاف، وتصدير CSV وJSON.

## الحسابات والاستئناف

- `--fresh` ينشئ جلسة منفصلة، بلا تنفيذات سابقة، و100 USDT لكل حساب جديد. قد تحدث صفقات جديدة فور وصول إشارة. لا يحذف أو يعيد كتابة الجلسات القديمة.
- لإيقاف الاثنين وحفظ الحالة، اضغط Ctrl+C في جلسة اللوحة. تبقى المراكز الافتراضية محفوظة وتتعطل مراقبتها حتى الاستئناف.
- للاستئناف: `bash run_paper_dashboard.sh` دون `--fresh`. لا تكرر `--fresh` إلا إذا أردت حسابين جديدين.
- الجلسات داخل `runtime/paper-dashboard/sessions/<session>/`؛ يشير `runtime/paper-dashboard/current` إلى الجلسة المختارة. اسم الجلسة ظاهر باللوحة.
- حالة كل بوت في `accounts/<bot>/state.json`، وWAL وسجل Khaled في مجلده نفسه. لقطات العرض في `data/` وسجلات stdout في `logs/`. دفاتر البوتين معزولة عن بعضها وعن Demo.
- لتصدير كامل التفاصيل من اللوحة: الإعدادات والسجل ← بيانات المراجعة JSON، أو سجل الصفقات ← CSV. تصدير JSON للعرض لا يستبدل نسخة مجلد الحساب وWAL عند الاستعادة.

## الإعدادات الفعلية

يستهدف Khaled قيمة مركز ثابتة 100 USDT في Paper. يحسب الكمية من سعر التنفيذ ويقربها حسب دقة العقد. الهامش المطلوب نحو 10 USDT عند رافعة 10×، وتُرفض الصفقة إذا لم يكف الهامش أو تجاوزت حدود التعرض أو حدود العقد. الوقف 8% من التنفيذ، والتريل يبدأ عند 1.5% ويتبع أفضل سعر بمسافة 0.6%. هذا التحجيم يخص الدخول الجديد، ويمكن استئناف الجلسة الحالية مع المراكز المحفوظة.

هذه الواجهة تقرأ الحالة ولا تعيد حساب TP/SL أو حجم الأوامر. تتعامل مع أسماء الخروج الحالية `HARD_SL` و`TRAILING_SL` وتعرض تفاصيل التنفيذ وسجل الرسوم. يحسب الصافي برسوم الدخول والخروج ولا يعامل تعبئة خروج جزئية كصفقة كاملة.

## عزل Paper عن Demo

المشغل يفرض `execution_mode('paper')` على Khaled طوال عمر العملية، حتى لو اختير testnet في ملف baseline لاحقًا. يتحقق من وضع البوت قبل بدء التشغيل. عامل Paper يزيل متغيرات مفاتيح Binance وTelegram والنشر السحابي من بيئته؛ لا يرسل رسائل أو أوامر إلى الحسابات. لا يقرأ `.env` ولا يشغل run_demo أو مشرف Demo.

لا تستخدم هذه اللوحة لإدارة مراكز Demo: حقائق Demo ومفاتيحه في ملفاتها السابقة لا تدخل جلسة Paper. `health` المنفصل على8080 يعطل في عامل Paper لأن اللوحة تعرض الصحة على8787، تجنبًا للتعارض مع مراقب Demo. لا تتغير إعدادات المصدر أو خدمة Demo بسبب ذلك.

اللوحة محلية loopback فقط، وترفض Host/Origin غير المحليين، وتتطلب رمز تحكم جلسة لعمليات التشغيل والإيقاف. إذا كان8787 مستخدمًا، يرفض المشغل البدء قبل تشغيل العاملين. لا تشغل عاملين على ملف الحالة نفسه؛ ملفات قفل الحساب تمنع ذلك.

## التحديث والفحوص

أوقف اللوحة، حدّث Git، ثم استأنف دون `--fresh`. إذا تغيرت سياسة التداول ورفضت الحالة القديمة التوافق، احتفظ بها وابدأ جلسة منفصلة بـ`--fresh` بدل تعديل JSON يدويًا.

```bash
python -m pytest -q
node --check paper_dashboard/app.js
bash -n run_paper_dashboard.sh
```

اختبارات الربط تشمل الجلسات الجديدة والاستئناف، حفظ الحسابات القديمة، رفض خلط Demo، مصدر كل عامل، منع التكرار، دورة دخول/خروج ببيانات وهمية، جمع الرسوم، التصدير والتحكم، وقفل المنفذ قبل تشغيل البوتات. ليست اختبار سوق حي أو تشغيلًا على جهاز أندرويد. Paper لا يحاكي التصفية والتمويل والتنفيذ الفعلي، ولا يعادل حساب Binance Demo.
